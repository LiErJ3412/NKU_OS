## 练习1：理解first-fit 连续物理内存分配算法（思考题）

### First-Fit 算法整体思想

核心思想是：**将物理内存划分为以页（4KB）为单位的块，用双向链表管理所有“连续空闲页块”，分配时从链表头部开始查找，找到第一个大小 ≥ 请求页数的空闲块即进行分配**。

在 ucore 中，First-Fit 通过 `struct Page` 描述每一页状态，仅将**空闲块的起始页**加入链表，并利用 `property` 字段记录连续空闲页数，从而高效管理内存。

---

### 函数分析

#### 1. `default_init()`
```c
static void default_init(void) {
    list_init(&free_list);
    nr_free = 0;
}
```

- **作用**：初始化物理内存管理器的内部状态。
- **细节**：
  - 调用 `list_init(&free_list)` 创建一个空的双向链表（哨兵节点），他的后面就将链接空闲块；
  - 将全局空闲页计数器 `nr_free` 赋值为0。
- **调用时机**：`pmm_init()` → `init_pmm_manager()`。

#### 2. `default_init_memmap(base, n)`
```c
static void default_init_memmap(struct Page *base, size_t n) {
    // 1. 清除所有页的 reserved 标志
    for (struct Page *p = base; p != base + n; p++) {
        assert(PageReserved(p));
        p->flags = p->property = 0;
        set_page_ref(p, 0);
    }

    // 2. 将整个块作为空闲块
    base->property = n;
    SetPageProperty(base);
    nr_free += n;

    // 3. 按地址升序插入链表
    if (list_empty(&free_list)) {
        list_add(&free_list, &(base->page_link));
    } else {
        list_entry_t* le = &free_list;
        while ((le = list_next(le)) != &free_list) {
            struct Page* page = le2page(le, page_link);
            if (base < page) {
                list_add_before(le, &(base->page_link));
                break;
            } else if (list_next(le) == &free_list) {
                list_add(le, &(base->page_link));
                break;
            }
        }
    }
}
```
- **作用**：将一段连续物理页（`[base, base+n)`）初始化为空闲块。
- **关键逻辑**：
  - **仅起始页 `base` 进链表**：通过 `SetPageProperty(base)` 标记其为“空闲块头”，`property = n` 表示连续空闲页数；
  - **链表按物理地址升序排列**：便于后续释放时合并相邻块；
  - **更新 `nr_free`**：记录总空闲页数。

#### 3. `default_alloc_pages(n)`
```c
static struct Page *default_alloc_pages(size_t n) {
    assert(n > 0);
    if (n > nr_free) return NULL;

    struct Page *page = NULL;
    list_entry_t *le = &free_list;
    // First-Fit 核心：找第一个 property >= n 的块
    while ((le = list_next(le)) != &free_list) {
        struct Page *p = le2page(le, page_link);
        if (p->property >= n) {
            page = p;
            break;  // 找到就停！
        }
    }

    if (page != NULL) {
        list_del(&(page->page_link));  // 从链表删除

        // 拆分剩余部分
        if (page->property > n) {
            struct Page *p = page + n;
            p->property = page->property - n;
            SetPageProperty(p);
            list_add(list_prev(&(page->page_link)), &(p->page_link));
        }

        nr_free -= n;
        ClearPageProperty(page);  // 不再是空闲块头
    }
    return page;
}
```
- **作用**：分配连续 `n` 页物理内存，也就是First-Fit的实现。
- **First-Fit 分配过程**：
  1. **遍历链表**（从低地址到高地址）；
  2. **找到第一个 `property >= n` 的空闲块**，那么就用这个空闲块分配很简单；
  3. **分配前 `n` 页**，若剩余则拆分为新空闲块插回原位置；
  4. **更新状态**：清除已分配块的 `PG_property`，减少 `nr_free`。

#### 4. `default_free_pages(base, n)`
```c
static void default_free_pages(struct Page *base, size_t n) {
    // 1. 检查并初始化页
    for (struct Page *p = base; p != base + n; p++) {
        assert(!PageReserved(p) && !PageProperty(p));
        p->flags = 0;
        set_page_ref(p, 0);
    }

    // 2. 创建新空闲块
    base->property = n;
    SetPageProperty(base);
    nr_free += n;

    // 3. 按地址升序插入链表（同 init_memmap）

    // 4. 向前合并
    list_entry_t* le = list_prev(&(base->page_link));
    if (le != &free_list) {
        struct Page *p = le2page(le, page_link);
        if (p + p->property == base) {  // 地址连续
            p->property += base->property;
            ClearPageProperty(base);
            list_del(&(base->page_link));
            base = p;
        }
    }

    // 5. 向后合并
    le = list_next(&(base->page_link));
    if (le != &free_list) {
        struct Page *p = le2page(le, page_link);
        if (base + base->property == p) {
            base->property += p->property;
            ClearPageProperty(p);
            list_del(&(p->page_link));
        }
    }
}
```
- **作用**：释放连续 `n` 页，并合并相邻空闲块。
- **关键逻辑**：
  - **安全检查**：确保释放的是“已分配”页（非 `reserved` 且非 `property`），保证不释放有用的页；
  - **合并条件**：
    - 向前：`p + p->property == base`（前一块结束页 = 当前块起始页）；
    - 向后：`base + base->property == p`（当前块结束页 = 后一块起始页）；
  - **合并后更新 `property` 并移除被合并块**，有效减少外部内存碎片。

---

### First-Fit 算法的改进空间

尽管 First-Fit 实现简洁高效，但仍存在以下不足：

**改用 Best-Fit**：遍历所有块，选择**最接近请求大小**的块，提高空间利用率,也就是练习二。

**引入分离空闲链表（Segregated Free Lists）**：按块大小分桶（如 1 页、2 页、4 页...），加速小块分配；

**使用 Buddy System**：保证块大小为 2 的幂，便于合并，显著减少碎片（适合页级分配），也就是后面的challeng。

First-Fit 是一个简单有效的基础分配策略，通过**链表管理空闲块 + 首次适应分配 + 释放时合并**，实现了高效的连续物理内存管理。其设计清晰体现了操作系统内存管理的核心思想：**以页为单位、动态分配、减少碎片**。但在高负载或长期运行场景下，可考虑更高级的分配算法以优化内存使用效率。

### 设计实现过程

Best-Fit算法的核心思想是：**在所有满足请求大小的空闲块中，选择“浪费最少”（即块大小最接近请求大小）的那个块进行分配**。相比 First-Fit 的“首次适应”，Best-Fit 能显著提高内存空间利用率，减少内部碎片。

我们的实现复用了 First-Fit 的数据结构和释放逻辑（`struct Page`、双向链表、合并机制），因为两者相比只需要修改分配函数`best_fit_alloc_pages` 的查找策略来实现Best-Fit：

1. **数据结构复用**：
   - 使用与 First-Fit 相同的 `free_area_t` 空闲链表；
   - 每个空闲块仍由起始页的 `property` 字段记录连续页数；
   - 链表按物理地址升序排列，便于释放时合并。

2. **分配逻辑修改**：
   - 遍历**整个空闲链表**（而非 First-Fit 的“找到即停”）；
   - 记录满足 `property >= n` 且 `property - n` 最小的块；
   - 分配该块的前 `n` 页，剩余部分（若有）拆分为新空闲块插回原位置。

3. **释放逻辑复用**：
   - 完全复用 First-Fit 的释放与合并逻辑；
   - 包括安全检查、链表插入、前后向合并等。

### 关键代码实现

#### 1. `best_fit_init_memmap(base, n)`
- 初始化一段连续物理页为空闲块；
- 将起始页 `base` 标记为“空闲块头”（`SetPageProperty(base)`，`property = n`）；
- 按物理地址升序插入空闲链表。

#### 2. `best_fit_alloc_pages(n)`
```c
static struct Page *best_fit_alloc_pages(size_t n) {
    assert(n > 0);
    if (n > nr_free) return NULL;

    struct Page *page = NULL;
    list_entry_t *le = &free_list;
    size_t min_size = nr_free + 1;

    // 遍历整个链表，找 property >= n 且 property - n 最小的块,这里就是主要实现的best-fit的逻辑，其实也很简单
    while ((le = list_next(le)) != &free_list) {
        struct Page *p = le2page(le, page_link);
        if (p->property >= n) {
            if (p->property - n < min_size) {
                min_size = p->property - n;
                page = p;
            }
        }
    }

    if (page != NULL) {
        list_del(&(page->page_link));  // 从链表删除

        // 拆分剩余部分
        if (page->property > n) {
            struct Page *p = page + n;
            p->property = page->property - n;
            SetPageProperty(p);
            list_add(list_prev(&(page->page_link)), &(p->page_link));
        }

        nr_free -= n;
        ClearPageProperty(page);  // 不再是空闲块头
    }
    return page;
}
```

#### 3. `best_fit_free_pages(base, n)`

- 检查释放页是否为“已分配”状态（非 `reserved` 且非 `property`）；
- 将 `base` 标记为新空闲块头（`property = n`，`SetPageProperty(base)`）；
- 按地址升序插入链表；
- 尝试与前后相邻空闲块合并（若地址连续）。

**分配流程**：

1. 遍历空闲链表，找到最佳匹配块（浪费最少）；
2. 从该块分配前 `n` 页；
3. 若有剩余，拆分为新空闲块插回原位置；
4. 更新 `nr_free` 并清除已分配块的 `PG_property`。

**释放流程**：

1. 安全检查：确保释放的是合法已分配页；
2. 创建新空闲块并插入链表；
3. 向前/向后合并相邻空闲块，减少外部碎片。

### Best-Fit 算法的改进空间

尽管 Best-Fit 提高了空间利用率，但仍存在以下不足，时间复杂度高O(n),产生大量微小碎片,无大小分类的管理

#### 改进方向：
- **引入分离空闲链表（Segregated Free Lists）**：按块大小分桶（如 1 页、2 页、4 页...），将 Best-Fit 限制在对应桶内，降低查找开销；
- **结合 Buddy System**：先用 Buddy 分配大块，再在大块内用 Best-Fit 分配小对象，兼顾速度与利用率；
- **定期整理内存**：通过内存紧缩（compaction）合并碎片（需支持动态地址重映射）。
