# 实验4 报告

## 🧠 重要知识点与原理映射
- **进程控制块（PCB）初始化**：`proc_struct` 中保存了调度所需的全部内核态元数据。实验中通过 `alloc_proc` 完成对状态、内核栈指针、页表根等字段的清零，呼应了原理课“PCB 构成决定调度粒度”的概念。
- **内核线程复制流程**：`do_fork` 负责申请内核栈、复制上下文、把新 PCB 链接到双向链表。它直观对应了 OS 原理里的 “fork = 复制父进程执行上下文 + 共享/复制地址空间”。
- **上下文与陷入帧**：`context` 只保留被 `switch_to` 使用的 callee-saved 寄存器，而 `trapframe` 则保存一次中断/陷入时的全部寄存器和 `sepc/sstatus`。这分别对应“调度上下文切换”和“异常返回现场恢复”两个层次。
- **中断屏蔽与原子切换**：`local_intr_save/restore` 以保存-恢复 SSTATUS 寄存器的 SIE 位保证 `proc_run`、`schedule` 等关键区间内的不可抢占，与“关中断实现临界区”的原理完全一致。
- **多级页表访问**：`get_pte` 两段近似代码对应 RISC-V SV39 两级页目录逐级下钻，体现了“树形页表层层索引”的思想。

## 📚 原理中重要但本实验未覆盖的点
- **进程/线程的用户态 Syscall 接口**：当前实验只创建内核线程，未体验用户态到内核态的 syscall/trap 过程。
- **调度策略与优先级**：调度器仍是最简单的循环搜索 RUNNABLE，没有实现多级反馈队列、时间片统计等高级策略。
- **按需分页与页面置换**：`copy_mm` 直接共享/忽略地址空间，尚未涉及写时复制、缺页异常处理等 VM 主题。

## ✅ 练习1：alloc_proc 初始化
### 实现概述
- 在 `alloc_proc` 中完成 `proc_struct` 全字段的零初始化：`state=PROC_UNINIT`、`pid=-1`、`runs=0`、`kstack=0`、`need_resched=false`、`parent/mm/tf=NULL`、`pgdir=boot_pgdir_pa`、`flags=0`，并清空名字与链表指针。
- 使用 `memset`/`list_init` 确保 context 与链表节点没有脏值，避免后续 `proc_list`/`hash_list` 遍历出现野指针。

### 问题：`context` 与 `trapframe` 的作用？
- `struct context`：只包含 `ra/sp/s0~s11` 等 callee-saved 寄存器，由 `switch.S`/`switch_to` 在调度时读写。它代表“调度器眼里的线程内核栈快照”。
- `struct trapframe *tf`：位于内核栈顶的一份完整 trap 保存区，含所有 GPR、`status` 与 `epc`。当线程经由 `forkret`/`forkrets` 或中断返回用户态时，需要依靠 `tf` 恢复现场。实验中 `copy_thread` 会把父进程 trapframe 拷贝到子进程的 `tf`，使其在第一次运行时像刚从 `kernel_thread_entry` 返回一样。

## ✅ 练习2：do_fork 资源分配
### 实现概述
1. **分配 PCB**：调用 `alloc_proc`，并把 `parent` 设为 `current`。
2. **申请内核栈**：通过 `setup_kstack` 分配 `KSTACKPAGE` 个页，并把虚拟地址存进 `proc->kstack`。
3. **复制/共享地址空间**：调用 `copy_mm`（当前内核线程场景下直接共享/忽略）。
4. **复制上下文**：`copy_thread` 按父进程 trapframe 填充子进程 `tf`，并把 `context.ra` 设为 `forkret`，保证切换到子进程后从 `forkrets` 正确返回。
5. **登记到全局表**：利用 `get_pid` 分配唯一 pid，随后 `hash_proc` 和 `list_add(&proc_list, …)` 把 PCB 放入哈希和双向链表，`nr_process++` 统计数量。
6. **唤醒**：`wakeup_proc` 将状态置为 `PROC_RUNNABLE`，最终返回新 pid。

### 问题：pid 是否唯一？
是。`get_pid` 维护 `last_pid/next_safe`：它在 `[1, MAX_PID)` 区间循环递增，若冲突会扫描 `proc_list` 寻找未占用 id，并将 `next_safe` 设为当前最小冲突 pid，从而保证即使存在大量僵尸进程也不会重复。因 `MAX_PID > MAX_PROCESS`，可确保当前进程集合内 pid 唯一。

## ✅ 练习3：proc_run 上下文切换
### 实现概述
- 若 `proc == current` 直接返回；否则保存 `prev = current`。
- `local_intr_save` 关闭中断，避免切换过程中被打断。
- 切换 `current` 指针，并调用 `lsatp(current->pgdir)` 切换 SATP，使得栈/页表立刻指向目标线程的地址空间（当前实验中都是内核页表，但接口已经就绪）。
- 通过 `switch_to(&(prev->context), &(proc->context))` 执行汇编级上下文切换。
- `local_intr_restore` 恢复中断使能。

### 问题：本实验期间创建并运行的内核线程数？
- **2 个**：`proc_init` 首先把当前 CPU 伪装为 `idleproc`（pid 0），随后用 `kernel_thread(init_main, …)` 创建 `initproc`（pid 1）。`make qemu` 日志中也可看到 `this initproc, pid = 1, name = "init"`，说明仅这两个线程被调度运行。

## 🔧 Challenge & 思考题
### local_intr_save/restore 如何开关中断？
- `local_intr_save(flag)` 内部调用 `__intr_save`：读取 `sstatus` 的 SIE 位判断当前是否已开中断，若开启则执行 `intr_disable()`（写 CSR 清 SIE）并返回 1，否则返回 0。`local_intr_restore(flag)` 再根据 `flag` 决定是否调用 `intr_enable()`（写 CSR 置 SIE）。因此二者实质是“保存现场 + 条件恢复”，保证在退出临界区前恢复到进入时的中断状态。

### get_pte 中两段相似代码的原因？
- RISC-V SV32/SV39/SV48 都采用“多级页表 + 每级 9/10 位索引”结构。`get_pte` 先定位第一级目录（`pdep1`），若不存在则按需分配一个新页并填入 `PTE_V`；然后对第二级（`pdep0`）做同样的事情。不同分页模式只是在“级数/索引宽度”上差异，因此代码结构近似——都是“判断目录是否存在 -> 如果需要则分配 -> 递归/迭代深入下一层”。

### 是否需要拆分“查找 PTE”与“分配 PTE”？
- 当前 `get_pte(pgdir, la, create)` 通过 `create` 参数决定是否分配，优点是：接口简单、页表遍历逻辑集中、能保证调用者永远拿到可写的 PTE。
- 若拆成 `lookup_pte` + `ensure_pte`，可以让只读遍历（如页表遍历器）避免意外分配，但会增加调用者负责两套流程的复杂度。综合 lab4 的规模，我认为保持单函数实现更利于维护，只需在调用处传入正确的 `create` 即可。
