## 练习 1：First-Fit 连续物理内存分配算法

### 函数职责与调用流程
1. `default_init`
	- 初始化 `free_area` 结构，将空闲链表 `free_list` 清空、空闲页计数 `nr_free` 置零。
	- 使得分配器处于“无可用页”的干净状态，等待后续 `init_memmap` 注入实际内存块。

2. `default_init_memmap(base, n)`
	- 接收一段 `[base, base+n)` 的连续页，依次清除 `flags`、将引用计数设为 0。
	- 仅在段首 `base` 记录块长度 `property = n` 并设置 `PG_property` 位，其余页 `property=0`。
	- 将该空闲块按物理地址升序插入 `free_list`，并累加 `nr_free += n`。

3. `default_alloc_pages(n)`
	- 顺序扫描 `free_list`，遇到第一个 `property >= n` 的块即停止。
	- 如块长度大于 `n`，在拆分点 `base+n` 新建块并重新挂回链表；原块被摘除、清除 `PG_property`。
	- 返回分配到的首地址，同时更新 `nr_free -= n`。

4. `default_free_pages(base, n)`
	- 将 `[base, base+n)` 逐页标记为空闲，设置 `property=n`、`PG_property`，并插回链表。
	- 依次尝试与前后邻接块合并：若相邻且连续则扩展 `property` 并摘除邻接节点，以减少外部碎片。

### 分配过程概述

1. `page_init` 探测到可用 DRAM 后调用 `default_init_memmap` 注入第一段空闲物理内存。
2. `alloc_pages` 调用 `default_alloc_pages` 顺序寻找首个可容纳请求的块，成功则拆分、失败返回 `NULL`。
3. `free_pages` 把页重新插入链表并做归并，保持链表按地址有序。

### 改进空间
- **时间复杂度**：First-Fit 在最坏情况下需扫描全表。可维护分段树/位图或按照块大小建立多级索引缩短查找路径。
- **碎片问题**：First-Fit 容易在低地址保留较小碎片。可周期性触发“紧凑/合并”策略或在分配时考虑 best-fit/worst-fit 结合的折中方案。
- **并发场景**：当前实现缺乏锁保护，未来在多核环境下应引入自旋锁或禁用中断的临界区。

## 练习 2：Best-Fit 连续物理内存分配算法

### 设计与实现说明

1. **初始化 `best_fit_init` & `best_fit_init_memmap`**
	- 与 First-Fit 类似，逐页清零状态、设置引用计数，并将 `base` 插入空闲链表。
	- 依旧保持链表按物理地址排序，为后续合并提供便利。

2. **分配 `best_fit_alloc_pages`**
	- 在遍历 `free_list` 时使用 `min_size` 记录当前满足请求的最小块长度。
	- 完整扫描后选出最贴合请求的块，减少外部碎片。
	- 剩余空间仍按 First-Fit 的方式拆分并重新挂入链表。

3. **释放 `best_fit_free_pages`**
	- 将归还的块插回链表后，分别尝试与前后相邻块合并，保持 property 信息正确。
	- `nr_free` 按释放页数增加，确保 `nr_free_pages` 统计准确。

4. **接入内核**
	- 在 `pmm.c:init_pmm_manager` 中把 `pmm_manager` 切换为 `best_fit_pmm_manager`，并通过 `make grade` 验证。

### 改进思路
- **查找效率**：当前 best-fit 仍需全表扫描，可使用平衡树/桶链表按照 `property` 排序加速定位近似大小的空闲块。
- **拆分策略**：可在拆分时根据剩余空间大小决定是否立即插入链表或暂存于小块缓存，有助于缓解碎片。
- **统计信息**：可以额外维护平均块大小、最大/最小块尺寸，辅助调试与后续调度策略。

### 与参考答案差异
- 参考答案采用了遍历中即时更新最优候选的写法，本实现同样如此，但在插入链表时报以“先判断小于、否则尾插”的两段式逻辑，以确保链表稳定有序。
- 自己的实现更强调注释与断言，方便后续扩展；若参考答案使用单向排序或多重链表索引，这里仍采用一条双向链表维持简单性。

## Challenge 讨论

### 1. Buddy System 分配器（未实现）
- **核心思想**：把内存分割为 2^k 大小的块，分配时找到最小满足的块，不足则不断分裂；释放时尝试与 buddy 合并。
- **实现要点**：需要对齐地址、维护多级自由链表、快速定位 buddy。若要接入 uCore，需改写 `pmm_manager` 接口，并在 `free_pages` 中循环合并。
- **计划**：后续若实现，会在 `struct Page` 中存储阶数，初始化时将探测到的空闲区按 `order` 拆分并挂入各级链表。

### 2. SLUB 分配算法（未实现）
- **主体思想**：在页分配器之上建立对象缓存，每个缓存维护 slab 链表（满/部分/空），以常量时间分配小对象。
- **难点**：需要为不同对象尺寸创建 `kmem_cache`，并处理 CPU 本地缓存、构造函数等；对 uCore 而言需扩展内核堆管理模块。

### 3. 获取物理内存范围的方法
- **基于固件接口**：当前实验通过设备树（DTB）向内核提供 `memory@` 节点，可在 OpenSBI/EFI 上通用。
- **BIOS/E820 表**：在 x86 平台可通过 BIOS 中断或 ACPI/E820 表获得物理内存布局。
- **自检方案**：最保守做法是以页为单位尝试读写并捕获异常，但效率低且可能破坏设备寄存器，不推荐。

## 知识点与 OS 原理对应关系

| 实验知识点 | 对应 OS 原理 | 含义与联系 | 差异/补充 |
| --- | --- | --- | --- |
| 物理内存探测（DTB） | 设备管理、引导阶段资源描述 | 通过设备树获得可用 RAM 范围 | x86 多用 BIOS/ACPI，本实验基于 RISC-V OpenSBI |
| 连续页分配（First-Fit/Best-Fit） | 内存分配算法 | 以页为粒度管理空闲区 | 工业实现多用分层/平衡树以提高效率 |

| 空闲链表维护 | 内存空闲表管理 | 使用双向链表跟踪连续块 | 实务中常结合伙伴系统、位图降低碎片 |
| 页表初始化（`satp`） | 虚拟内存与地址转换 | 建立内核页表并写入 satp 寄存器 | 实验仅构建内核空间映射，尚未涉及用户态隔离 |

## OS 原理中未覆盖或未在实验呈现的重要内容
- **页面置换算法**（如 LRU/Clock）：实验未涉及交换区与缺页中断处理。
- **系统调用与用户态过渡**：尚未开启 trap/中断路径，未体验内核/用户态切换。
- **同步原语与并发控制**：当前分配器无锁，未考虑多核竞争。
- **内存保护与权限**：未设置页表访问权限位，也无写时复制等策略。
- **内核堆与 kmalloc**：实验只实现了物理页分配，未覆盖内核对象分配器。
